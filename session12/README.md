# Session 12 — Firebase Setup and Authentication

This session gives the app its first backend. We connect it to Firebase and
add sign-in: users can register and sign in with an email and a password, stay
signed in after the app restarts, and sign out. Each user also gets their own
document in Firestore, at `Users/{uid}`. The tasks are not in Firestore yet;
that's next session.

**Project Setup Instructions:**

1. Create a new Flutter project.
2. Add the `lib/` folder to your project directory.
3. Add the dependencies:
   `flutter pub add flutter_riverpod http firebase_core firebase_auth cloud_firestore`
4. Run the following command in your terminal: `flutter pub get`
5. Set up your Firebase project and connect it (see the next section). The
   `lib/firebase_options.dart` in this folder is only a placeholder;
   `flutterfire configure` replaces it with your own project's settings.

**Firebase setup (once):**

1. Go to the [Firebase console](https://console.firebase.google.com) and create
   a project.
2. **Authentication → Get started → Sign-in method → Email/Password →
   Enable → Save.**
3. **Firestore Database → Create database →** pick a location **→ Start in
   test mode → Create.**
4. Install the tools (once per computer):
   - the Firebase CLI: `curl -sL https://firebase.tools | bash` (or
     `npm install -g firebase-tools`), then `firebase login`
   - the FlutterFire CLI: `dart pub global activate flutterfire_cli`
     (on Linux, if `flutterfire` is not found:
     `export PATH="$PATH:$HOME/.pub-cache/bin"`)
5. In your project folder, run:
   `flutterfire configure --project=YOUR-PROJECT-ID --platforms=web,android`
6. Run the app: `flutter run -d chrome`, or on an Android emulator/phone.
   Firebase does not support Linux desktop apps, so use Chrome or Android.

To check that it's connected: the terminal prints
`Connected to Firebase: YOUR-PROJECT-ID`, and after you register, the email
appears in **Authentication → Users** and a document appears in
**Firestore → Users**.

**What changed since session 11**

The tasks page, the task controller, the quote and the `services/` folder are
unchanged.

- `firebase_options.dart` — NEW. Generated by `flutterfire configure`. Tells
  the app which Firebase project to talk to.
- `models/user_model/user_provider_model.dart` — NEW. `UserProvider`: the
  user as our app stores it (`uid`, name, email, `creationTime`), with
  `fromMap()` and, new this time, `toMap()` to save it. The date is saved as
  text with `toIso8601String()`.
- `services/firebase/crud_firestore.dart` — NEW. `CRUDFirestore`, our
  wrapper around Firestore, like `Services` is around `http`:
  `setDocument()` and `getDocument()`.
- `Controllers/provider_account.dart` — NEW. `ProviderAccount`: `register()`,
  `signIn()`, `restoreSession()` and `signOut()`. After signing in it reads
  the user's document from Firestore, or creates it the first time.
- `Controllers/app_controllers.dart` — added `accountProvider`.
- `Views/home_page.dart` — `StatelessWidget` → `ConsumerStatefulWidget`.
  Shows a login form (email, password, Sign in, Register) when signed out,
  and a small profile (email, View my tasks, Sign out) when signed in.
- `main.dart` — `main()` is now `async`: it starts Firebase and restores the
  session before `runApp()`.

**What we learned**

What a backend is and what Firebase gives us, connecting an app with
`flutterfire configure`, an `async` `main()` with
`WidgetsFlutterBinding.ensureInitialized()` and `Firebase.initializeApp()`,
Firebase Authentication with email and password, Firestore collections,
documents and fields, `toMap()` for saving data, `try` / `catch` / `finally`,
showing errors in a `SnackBar`, `context.mounted` after an `await`, and a
screen that changes on sign-in state without any navigation.

**Common problems**

| What you see | Fix |
| --- | --- |
| `operation-not-allowed` | Turn on Email/Password in **Authentication → Sign-in method** |
| `permission-denied` | Firestore is not in test mode: check **Firestore → Rules** |
| `The database (default) does not exist` | Create the Firestore database in the console |
| `email-already-in-use` | That email is already registered: use Sign in |
| `weak-password` | Use at least 6 characters |
| Blank page in Chrome | Run `flutterfire configure` again with `--platforms=web` |
| Changes in `main.dart` don't show | Hot restart (`R`), not hot reload |
